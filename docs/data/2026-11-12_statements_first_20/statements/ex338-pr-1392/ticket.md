When drafting a player with `Admin.draft_player/2`, extend the operation returned to include one additional decision. The existing draft operations must stay exactly as they are, in the same order: `:draft_pick`, `:roster_position`, `:unavailable_draft_queues`, `:drafted_draft_queues`. Only append a new operation when the special case below applies; otherwise return the original multi unchanged with no extra entry.

The new behavior is about the pick immediately after the current pick in the same fantasy league, ordered by `draft_position`. Do not look across leagues. Do not skip past a pick. Look up the first pick in the same league whose `draft_position` is strictly greater than the current pick's `draft_position`. If there is no such pick, do nothing.

If that next pick is a keeper and already has a fantasy player assigned (`is_keeper` is true and `fantasy_player_id` is not nil), then it should have its `drafted_at` set to the current UTC time, truncated to whole seconds. This should be part of the same multi as the rest of the draft, under an operation named exactly `:next_keeper_drafted_at`, and when present it must be the last operation in the multi. It should update the next pick's `drafted_at` even if that field already has a value.

Examples: current pick at `draft_position` 1.0; next pick at 2.0 is a keeper with a player, so drafting changes 2.0's `drafted_at`. If the 2.0 pick is not a keeper, leave 2.0 alone and do not go looking for a later keeper at 3.0. If the 2.0 pick is a keeper with no `fantasy_player_id`, leave it alone as well. If there is no later pick in the league, no `:next_keeper_drafted_at` operation is added.

This must also work through `DraftPicks.draft_player/2`: when the multi is executed for a valid draft, the next keeper pick's `drafted_at` must actually be persisted, not just present in the built multi. It needs to participate in the same transaction as the other draft changes, so a failure elsewhere rolls it back too. Existing invalid-parameter behavior and the existing multi contents should not change otherwise.

Out of scope is changing how current picks are drafted, changing roster positions, changing draft queues, or updating any pick other than that single immediate next pick. The decision is deliberately not “find the next keeper”; it is “check the immediate next pick, and only update it when it is already a keeper with a player.”
