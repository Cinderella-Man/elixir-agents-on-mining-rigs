The MCP endpoint at `/api/v1/mcp` is POST-only. Keep the existing POST behaviour exactly as it is, including the authenticated JSON-RPC handling and the existing `initialize` result with `serverInfo.name` set to `ex338`.

For any non-POST request to `/api/v1/mcp`, including GET, HEAD, OPTIONS, PUT, PATCH and DELETE, return status 405 with the normal JSON error body. The `error` value must contain the literal text `use POST`, and the response must have an `Allow` header whose only value is `POST`. Do not include OPTIONS in `Allow`. This 405 response must happen before any authentication or content negotiation, so a request with no token and no `Accept`/`Content-Type` headers still gets 405, not 401 or 404. POST requests must continue to reach the existing handler and authentication flow.

Also make the Authorization bearer scheme case-insensitive, as HTTP auth schemes are. `Bearer <token>`, `bearer <token>`, `BEARER <token>`, and other case variants should authenticate when the token is valid, with whitespace around the token trimmed. Reject with the existing 401 JSON error when the scheme is anything other than bearer, such as `Basic <token>`, when the header is missing or malformed, when the token is empty or whitespace-only, or when the token itself is invalid. Token lookup and the rest of the API behaviour stay unchanged.
