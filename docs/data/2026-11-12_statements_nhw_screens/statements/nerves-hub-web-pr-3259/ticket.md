Feature: token path parameters must not appear in request logs or traces.

Some routes put a secret directly in the path as a `:token` parameter, for example the CLI login polling token and the links in password reset, invite, and email confirmation emails. Any future route with a `:token` path parameter should be handled automatically; do not hard-code the current set of routes.

Expose a public helper, `NervesHub.Telemetry.RequestPath.recordable/1`, that returns the request path that is safe to record, without the query string. It should accept either a connection or a map with `request_path`. When the request has a matched path parameter named `token` with a binary value, replace every path segment in the full request path that is exactly that value with the literal `[FILTERED]`, preserving the rest of the path and any mount prefix. For example, `/api/auth/cli_session/2f1b0c7e` should become `/api/auth/cli_session/[FILTERED]`, and `/invite/abc123/accept` should become `/invite/[FILTERED]/accept`. If there is no matched `token` path parameter, or the path did not match a route, return `request_path` unchanged. Do not filter based on other parameters that merely have the value `token`; for instance `/org/token/token/devices` with `org_name` and `product_name` equal to `token` must remain unchanged. A path with no route matched, such as `/auth/cli/2f1b0c7e`, also stays as it came.

The request logger should record the same path, so request log lines show `[FILTERED]` instead of the token. If a query string is present, it is still appended after `?` unchanged; this feature covers tokens carried as path parameters, not query parameters. Requests without a token path parameter must keep their existing log formatting and path exactly as before.

Traces must present the same filtered path in the span’s `url.path` attribute. A request span may start with the raw path before routing has identified the token, so the attribute must be corrected once routing has the token and must be correct for the exported span. This includes requests whose token is unknown or whose controller raises afterward and is rendered as a 404: the path must still be filtered, while the response status is unchanged. Likewise, a successful CLI poll should export the filtered path, not the raw token. Paths that do not have a token path parameter, websocket span naming, and all non-path behavior should remain unchanged. The actual routing, parameters, authentication, and responses must not be altered; only the path written to logs and traces is affected.
