The account details form doesn't change a password, but posting a password parameter through it currently updates the password hash. Make update_changeset/2 only handle the account details fields (name/email): it should ignore password and password_hash, and password changes should remain solely through password_changeset/2. Also, Auth.return_to_target/1 still accepts return URLs that a browser may send somewhere other than the parsed host; it should return :default for any URL containing backslashes, whitespace or control characters, or credentials, for example "https://evil.example.com\\@admin.example.com/" and "https://user@admin.example.com/". An allow-listed URL with a path and query must still be returned verbatim.
