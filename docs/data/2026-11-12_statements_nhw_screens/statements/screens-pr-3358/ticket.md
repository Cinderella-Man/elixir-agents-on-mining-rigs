Alert.stale?/1 is still keying off active periods, so old alerts are being treated as stale for the wrong reason and Symphony-related closures can slip through. Make it depend only on the alert: return true only for a :station_closure or :stop_closure whose informed entities include the stop id "place-symcl"; everything else is fresh regardless of active_period. For example, %Alert{effect: :station_closure, informed_entities: [ie(stop_id: "place-symcl")]} is stale, while %Alert{effect: :detour, informed_entities: [ie(stop_id: "place-pktrm")]} is not. The callers that suppress stale alerts should pass through the location context only, with no now argument, and when there is no location context a stale alert is suppressed. Keep the existing boundary exception: only suppress a stale alert when the screen is not inside that alert's affected location, so a stale closure affecting the screen's own stop still shows up.
