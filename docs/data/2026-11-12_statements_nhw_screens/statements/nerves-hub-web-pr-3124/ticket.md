When a priority-queue device gets skipped, for example because it's in the penalty box, and the normal queue has no free slots, the orchestrator stops even though that skip freed a priority slot. The next eligible priority device then waits until something else kicks the orchestrator, so a group with one priority slot and one already-used normal slot can leave a waiting priority device unscheduled. If any priority device was skipped, the orchestrator should treat that as more work and run again so the freed priority slot is filled, even when the normal queue is full.
