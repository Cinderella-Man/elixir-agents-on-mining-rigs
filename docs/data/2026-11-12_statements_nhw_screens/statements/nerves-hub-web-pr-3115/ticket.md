Root CAs generated by LibreSSL's `openssl req -x509` (including the ones made in Step 1 on the CA page) omit the Authority Key Identifier; they should still be accepted as long as they have a Subject Key Identifier, storing `aki` as `nil` and the `ski` as-is. `NervesHub.Certificate.get_aki/1` should return `nil` when the extension is absent, and the SSL verify path must treat a known root CA with no AKI as valid once registered while still returning `:unknown_ca` before registration. A certificate with neither AKI nor SKI must not pass as `aki == ski`; it should fail with `:unknown_ca`. Device certificate registration still requires AKI, so a device cert without one should return 422 with `{"aki" => ["can't be blank"]}`. On CA creation require SKI and return a 422 `ski` error whose message includes "Subject Key Identifier"; on the new CA page show a SKI-specific explanation containing "no Subject Key Identifier extension" in an element with id `missing-ski-error`, without also showing the generic "Something went wrong!" banner.
