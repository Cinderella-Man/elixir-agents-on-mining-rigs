Alerts currently keep an informed entity's route as just the route ID string, so code that expects the actual route can't use it. Change the informed entity route to be the full `Screens.Routes.Route` struct resolved from the API's included route data, with its `line` populated from the included line data; when the raw entity has no route, keep it `nil`. Fetching alerts should request routes and their lines, so a Blue alert comes back with something like a `Screens.Routes.Route` whose `id` is `"Blue"` and `line` is a `Screens.Lines.Line`, not the string `"Blue"`.

Anywhere the app currently compares or consumes the informed entity route should use the route's ID, and behavior should otherwise stay the same: an entity with a route and no stop counts as whole route, one with a route, direction, and no stop counts as whole direction, and a nil route does not. Whole-route delay consolidation should group by route ID, and route filtering, route listings, and alert matching should keep returning the same route IDs. Missing routes should be ignored safely rather than crashing or matching route-specific logic.
