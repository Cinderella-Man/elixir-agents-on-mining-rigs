A connecting device can ask for arbitrarily large PBKDF2 work and key lengths through `x-nh-alg` (for example `NH1-HMAC-sha256-100000000-1024`), and we process it before rejecting a bad signature. Limit that: iterations must be 1 to 10,000 and key length 1 to 64, inclusive. 10,000 and 64 should still work, while 10,001, 65 and zero must be refused without deriving the key and reported as invalid auth with reason `{:error, :key_derivation_out_of_range}`. The usual 1,000 iterations and 32-byte key must continue to work.
