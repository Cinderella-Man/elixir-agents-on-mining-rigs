`enforce_failure_limits/2` can leave behind a "Device automatically blocked" audit log when the device update that was supposed to put it in the penalty box fails. That audit entry should only exist if the penalty was actually recorded. Make the device penalty and its audit entry go through together, with the inflight update cleared; if the device update fails, keep the warning and clear the inflight update, but leave no audit entry and still return `{:error, :updates_blocked, device}`. On success, keep logging the penalty, publish the normal `updated` event on `DeviceEvents.topic(device)` so subscribers receive `%Broadcast{topic: topic, event: "updated"}`, and return the updated device in `{:error, :updates_blocked, device}`.
